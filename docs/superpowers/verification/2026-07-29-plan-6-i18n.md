## Deviations from Plan

1. **Task 1 — `use crate::dialog_i18n;` import:** The plan's Task 1 Step 4 did not mention adding a `use` import to `commands.rs`. Without it, the compiler raised `error[E0433]: cannot find module or crate 'dialog_i18n'`. The subagent added `use crate::dialog_i18n;` at line 11 of `commands.rs` to resolve this — matching the pattern used for other `use crate::*` imports in the file. This is the minimum change needed to make the plan's exact call-site code compile.

2. **Task 4 — `loadTsModule` bug fix:** The plan's `loadTsModule` function used `data:text/javascript;base64,...` URLs to load the transpiled module. This fails because `messages.ts` contains `import { zhTW } from "./zh-tw"` — a relative specifier that cannot be resolved against a `data:` URL (URL spec limitation, not Node-specific). Fixed by replacing `loadTsModule` with `loadMessagesModule` which transpiles both `messages.ts` and `zh-tw.ts`, then inlines the `zhTW` export declaration directly into the messages module body (replacing the import statement with `const zhTW = {...}`). After inlining, the module has no relative imports and the `data:` URL loads cleanly.

3. **Task 2 — test runner substitution:** The plan's Task 2 Step 3 suggested `pnpm test scripts/check-brand-policy.test.mjs`, but `vitest`'s `include` config (`src/**/*.{test,spec}.{ts,tsx}`) excludes `scripts/*.mjs`. The brand-policy tests use `node:test` (not vitest), so the correct invocation is `node --test scripts/check-brand-policy.test.mjs`. All 9 tests pass under this runner.

## Known Gaps

- **React context provider for locale:** the codebase prop-drills `locale: Locale` through ~30+ components instead of using React context. Plan 6 did NOT introduce a context — this is a future refactor, not a gap. The current pattern works and is SSR-friendly (per `docs/upstream-history/grok-app/llm-wiki/i18n.md` design notes).
- **OS-level locale auto-detection:** Plan 6 did not add first-run OS locale detection (e.g. via `tauri-plugin-localization` or `app.getLocale()`). Locale remains settings-driven (`AppSettings.locale` defaulting to `"en"`). This is a deliberate product decision; users switch via Settings → Language.
- **OMP runtime i18n:** the OMP runtime (`runtime/oh-my-pi/`) has no i18n layer and is intentionally a backend/CLI. Runtime user-visible strings (TUI labels, agent metadata) are out of scope for the desktop app's catalog.
- **Frontend mapping from v1 `messageKey` to `v1Error.*` keys:** the catalog now has the 9 `v1Error.*` keys, but there is no helper function that maps a v1 error's `messageKey` (e.g. `"runtime.unavailable"`) to the frontend catalog key (e.g. `"v1Error.runtimeUnavailable"`). This mapping is a future UI task — the catalog entries are in place for when the UI layer is wired.
