# Plan 10: 1.0 Acceptance Matrix — Implementation Plan Outline

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Define and execute the 1.0 release acceptance matrix: capability baseline 100% coverage verification, cross-platform acceptance testing, performance benchmarks, security audit, documentation review, and release readiness sign-off.

**Architecture:** A formal acceptance matrix document (`docs/release/1.0-acceptance-matrix.md`) lists every capability, test, benchmark, and audit item with a sign-off column. The matrix is executed across macOS, Windows, and Linux; each item gets a PASS/FAIL/BLOCKED status with evidence (test output, screenshot, audit report). Release 1.0 ships only when all items are PASS or explicitly waived with documented justification.

**Tech Stack:** Vitest (existing test suite), `cargo test` (Rust), manual testing checklist, `scripts/check-*.mjs` (brand/provenance/i18n/legal gates), performance benchmarking tools (TBD).
